NOA Interface Hub

보험사가 외부 기관 · 사내 시스템과 주고받는 수십 개의 인터페이스를 한 화면에서 등록 · 실행 · 감시 · 분석하는 통합 관제 플랫폼. AI 어시스턴트가 과거 유사 장애 사례를 찾아 원인 가설과 조치 절차를 자연어로 제안합니다.

Stack
Vue 3 · FastAPI · PostgreSQL · Redis
Protocols
REST · SOAP · SFTP · MQ · BATCH
Security
JWT · AES-GCM · RBAC · Audit
AI
Multi-LLM + TF-IDF Fallback
01

시스템 개요

대상보험사 운영팀 (외부 기관 인터페이스 담당자, 사내 시스템 운영자, 감사 담당)
해결프로토콜 파편화 / 장애 원인 파악 지연 / SLA · 감사 자료 수작업 / 선제적 이상 감지 부재
차별점단순 모니터링을 넘어 AI 가 과거 사례를 인용해 답변, 그리고 운영 보안 · 감사가 1급 시민

지원 프로토콜  ·  REST · SOAP · SFTP · MQ (Redis 시뮬) · BATCH

04

화면별 운영자 가이드

4.1
로그인
  • 5회 연속 실패 시 30분 자동 잠금 (HTTP 423). ADMIN 이 사용자 관리에서 즉시 해제.
  • 첫 로그인 · 리셋 직후엔 강제 비밀번호 변경 다이얼로그 (다른 화면 접근 차단).
4.2
대시보드

의도 — 지금 시스템 전체 상태를 한 눈에. 새 장애 즉시 인지.

기능

  • 24시간 KPI 4종: 총 호출 / 성공률 / 평균 응답 / 실시간 장애 카운트
  • 최근 6시간 호출량 · 응답시간 시계열 (분 단위)
  • 실시간 호출 라이브 피드 (WebSocket)
  • 시간대 × 인터페이스 히트맵 (호출량 / 실패율 토글)

사용 팁

  • 히트맵 범례 칩 클릭 → 해당 구간만 강조, 나머지 dim.
  • 우상단 종 숫자 = 미해결 장애. 클릭하면 장애 페이지 미해결만 모드 진입.
4.3
토폴로지

의도 — 시스템 구조 조망. "어느 사내 모듈이 어떤 외부 기관에 의존하는가".

기능

  • 좌측 사내 핵심 (보험금계산, CB평가)
  • 우측 상 외부 제휴사 (PG, 메시징, 마이데이터)
  • 우측 하 규제기관 (금감원, 신용정보원, 국세청, 보험개발원)
  • 카드 색 = 최근 N일 헬스 (정상/주의/장애/데이터 없음)
  • 1일 / 7일 / 30일 윈도우 토글, 카드 클릭 → 인터페이스 페이지 드릴다운
4.4
인터페이스 관리

의도 — 모든 외부 · 내부 연동의 마스터 데이터 통합 관리.

기능

  • 분류 · 프로토콜 · 기관 다중 필터, 활성/휴지통 토글
  • 행마다: 분류 · 방향(IN/OUT) · 프로토콜 · 스케줄 · 상태 · 인증키 D-N · 재시도 횟수 칩
  • 액션: 시크릿 조회 (ADMIN, 사유 필수), ▶ 실행, 🔕 음소거, 수정, 보관 처리

등록 폼 핵심

  • 분류(사내/제휴/규제) · 방향(OUT/IN) · cron 미리보기 (다음 N회 실행 시각)
  • 호출 안정성 — timeout · 재시도 횟수 · backoff 초 (REST/SOAP 만, 401·422 즉시 종료)
  • 인증 키 만료일 (D-7 이내 자동 알림)
4.5
호출 로그 · 재처리

의도 — 모든 호출의 흔적을 검색 · 재처리 · 드릴다운.

  • 1차 필터: 인터페이스 · 상태 · 프로토콜 · 키워드 · 실패만
  • 2차 필터: 시간 구간 (1h/6h/24h/7d 빠른 선택), 숫자만 입력해도 자동 YYYY-MM-DD HH:mm 마스킹
  • 상세: Request/Response JSON · stacktrace · 재처리 체인 보기
  • 재처리된 호출은 ↻ 자동 제거, 일괄 재처리는 체크박스 선택 → 안전 가드
4.6
장애 (Incidents)

의도 — 같은 원인 반복 실패는 묶어 알림 폭주 차단.

  • severity 칩 (참고/주의/긴급), 발생 기간 컬럼, "진행중" 라벨
  • "관련 호출" 칩 → 묶인 호출 다이얼로그
  • 재처리 옵션: 최신 1건만(기본 안전) / 전체 N건(confirm)
  • 같은 (interface, type) 조합은 미해결 1건만 유지 → 100회 실패해도 알림 1번
4.7
성능 관리

의도 — 백분위 · 처리량 · 느린 Top-N 으로 SLA 위반 사전 포착.

  • 처리량 (TPS) · p95 응답시간 24h 시계열, 느린 호출 Top 10
  • 인터페이스별 p50 / p95 / p99 / max + 처리량 + 실패율
  • p95 가 SLA 기준. 떨어지면 인터페이스별 정렬로 원인 분석 시작.
4.8
SLA 리포트

의도 — 월/분기 SLA 성과 시각화 + 감독당국 보고 자료 생성.

  • KPI 4종: 인터페이스 수, 평균 가동률, 가동률/응답 목표 달성률
  • 일별 SLA 충족 캘린더 (달성/부분/미달/데이터없음 + 범례 필터)
  • 인터페이스별 누적 표 + 월/분기 추이 차트 (6개월 이상 보장)
  • Excel 내보내기 + 프린트/PDF (A4 가로 최적화)
4.9
AI 분석 어시스턴트

의도 — "지금 무슨 일이?" / "과거에 본 적 있나?" 자연어로 질의.

  • 진행 단계별 메시지 회전 (질문 의도 → 유사 사례 → 컨텍스트 전달)
  • 답변 markdown 렌더 + incident 링크 자동 드릴다운
  • 추천 프롬프트 순위: 현재 장애 > 자주 묻는 질문 > 템플릿
  • 칩 메타: intent · mode(LLM/fallback) · provider · ⚡cached · repeated · fallback 체인
  • LLM 미설정 시 TF-IDF fallback — 검색은 항상 동작
4.10
자동 복구 분석

의도 — 재시도 정책이 실제 SLA 를 개선하는지 정량 측정.

  • KPI 4종: 총 호출 / 재시도 발생 / 복구 / 최종 실패
  • "재시도 도입 효과" 배너 — "최근 N일간 X건 자동 복구"
  • 인터페이스별 표 + 복구율 progress bar (60%↑ 효과 / 30%↑ 보통 / 미만 재검토)
  • SFTP/MQ/BATCH 는 멱등성 문제로 자동 재시도 미적용 ("정책 없음")
4.11
알림 룰 ADMIN

의도 — 전사 공통 알림 정책. 인터페이스 설정 위에 한 번 더 필터링.

  • 심각도별 채널 (참고/주의/긴급) — 인앱 · Slack · 이메일
  • 야간/주말 끄기 + 긴급 예외 옵션
  • "미리 보기" 표 — 지금 시각 기준 실제 발송 채널 시뮬
  • 인터페이스 음소거 ∩ 전역 룰 = 실제 발송
4.12
감사 로그 ADMIN/VIEWER

의도 — 누가 · 언제 · 무엇을 · 어디서 영구 기록 (금감원 감사 대응).

  • 사용자 · 액션 · 자원종류 · 기간 필터, 변경 전/후 JSON 비교
  • Excel 내보내기, append-only (수정/삭제 불가)
  • 인터페이스/장애/사용자/로그인/비밀번호/알림룰 모든 변경 기록
4.13
사용자 관리 ADMIN

의도 — 계정 라이프사이클 + 보안 사고 대응 (퇴사 · 탈취).

  • 신규 생성 + 임시 비번 → 첫 로그인 강제 변경
  • 🔓 잠금 해제, 🚪 강제 로그아웃 (모든 세션 즉시 종료)
  • 강제 로그아웃은 session_version 카운터 방식 — JWT stateless 인데도 즉시 무효
05

설계 결정 — 왜 이렇게 만들었나

5.1LangChain · FAISS 대신 멀티 LLM + TF-IDF

초기 기획은 LangChain · FAISS · OpenAI Embedding 이었지만 실제로는 httpx 직접 호출 + scikit-learn TF-IDF 로 갔습니다.

  • 단일 프로바이더 종속 회피 — 멀티 프로바이더 + 자동 fallback 으로 한 곳 실패 시 다음으로 전환
  • 임베딩 비용 · 복잡도 — 데모 규모(과거 incident 수십 건)엔 TF-IDF 로 충분, 메모리만 사용
  • 환각 방지 — 의도 분류(stats/case/config/general)로 stats 질문은 실시간 DB 표, case 는 RAG, config 는 메타 표만 — system prompt 로 "데이터에 없는 일반론" 추가 금지

5.2incident dedup — 알림 폭주 방지

같은 (interface, type) 조합 미해결 incident 는 1건만. KIDI 가 100번 연속 실패해도 운영자에게 incident 1건 + 알림 1번. 실제 실패 호출 100건은 call_logs 에 그대로 남아 드릴다운 가능.

PagerDuty / Opsgenie / Datadog 의 alert grouping 과 같은 패턴. 야간 · 휴일 호출 폭주 방지가 핵심.

5.3자동 재시도 — REST/SOAP 만 적용

SFTP/MQ/BATCH 는 멱등성 보장이 어려움 (PUT 두 번이면 파일 두 개, MQ 는 메시지 두 번 소비). 네트워크 일시 장애 흡수 가치보다 중복 처리 위험이 큼.

REST/SOAP 도 401 · 422 는 재시도 제외 — 키 무효 / 페이로드 형식 오류는 재시도해도 같은 결과.

5.4음소거 vs 알림 차단의 분리

"음소거" 한 인터페이스라도 incident 자체는 정상 생성. 대시보드 카운트도 갱신. WS broadcast 는 항상, 다만 toast/Slack/Email 만 skip.

기록은 살아있고 알람만 끔 — 정기 점검 시간에도 사고 발생 가능성을 잃지 않음.

5.5keep-alive 페이지 캐시

모든 페이지를 컴포넌트 인스턴스 캐시 — 다른 페이지 갔다 돌아와도 필터 · 검색 · 답변 · 스크롤 유지. 로그아웃 시 자동 리셋. WebSocket 라이브 데이터는 keep-alive 와 무관하게 항상 push.

5.6시크릿 평문 노출의 통제된 경로

저장은 AES-GCM 암호화. 평문 조회는 ADMIN + 사유 필수 + 감사 로그 기록 + 1회만 노출 (다이얼로그 닫으면 메모리에서도 사라짐).

목적은 키 만료 트러블슈팅 / 담당자 인계 / 외부 도구 재현 — 무분별한 노출은 막되 정당한 사유 시 추적 가능한 형태로.

07

성능 · 한계

현재 데모 규모

  • 인터페이스 18개, 60일 호출 로그 21,000건
  • p95 응답시간 100~500ms (외부 호출 제외, 내부 API 기준)
  • AI 분석: 캐시 hit 즉시, miss 시 LLM 호출 3~10초
  • WebSocket 라이브: ms 단위 push

스케일 한계

  • DB 마이그레이션은 데모 한정 인라인 (ADD COLUMN IF NOT EXISTS). 실 운영엔 Alembic 필요.
  • 호출 로그 수백만 건 누적 시 인덱스 추가 (interface_id × called_at 복합) + 파티셔닝 검토.
  • AI 분석 캐시는 단일 Redis. 다중 백엔드 인스턴스 시 그대로 동작 (Redis 공유).
  • WebSocket 은 단일 프로세스 메모리 connection 보관. 멀티 프로세스 시 Redis pub/sub 또는 외부 메시지 브로커 필요.

LLM 프로바이더 키 미설정 시 정상. backend/.env 의 AI_PROVIDER 를 mistral/anthropic/openai/huggingface 중 하나로 + 해당 키 + 재기동.
Q3AI 호출이 매번 90초 타임아웃
외부망 차단 또는 LLM 측 지연. AI_FALLBACK_CHAIN 으로 다른 프로바이더 자동 전환, TF-IDF 로 떨어져도 과거 사례 검색은 동작.
Q4호출 로그가 비어있음
데모 시드 미실행. docker compose exec backend python -m app.scripts.seed_demo.
Q5대시보드 좌상단이 OFFLINE
WebSocket 연결 실패. 하드 리로드 (Ctrl+Shift+R) + 백엔드 컨테이너 상태 확인.
Q6"column does not exist" 에러
마이그레이션 누락. 백엔드 재기동 시 자동 적용 (ADD COLUMN IF NOT EXISTS).
Q7시각이 UTC 로 보임
컨테이너 TZ=Asia/Seoul + PostgreSQL 세션 timezone 확인. Docker 재시작 후 seed_demo 재실행.
Q8Slack / Email 알림이 안 옴
SLACK_WEBHOOK_URL / SMTP_HOST 미설정이면 자동 skip. 알림 룰의 "미리 보기" 표에서 실제 발송 채널 확인.
Q9"INBOUND 인터페이스는 실행할 수 없습니다"
정상 동작. INBOUND 는 외부가 우리 webhook 을 호출하는 구조라 능동 실행 불가. 외부에서 /api/call-logs/ingest 로 결과 push.
Q10▶ 실행했는데 우상단 toast 가 안 뜸
같은 (인터페이스, 오류 유형) 조합 미해결 incident 가 이미 있으면 alarm fatigue 방지로 dedup 됩니다. 페이지 내 빨간 snackbar + "장애 보기" 는 항상 뜨므로 그쪽으로 진입.
